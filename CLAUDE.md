# Project instructions

- When fixing a GitHub issue: after the fix is verified and pushed, leave a
  comment on the issue stating what was done (not just a `Closes #N` commit
  message that silently auto-closes it with no explanation).
- When implementing a new feature: check it against [FEATURES.md](FEATURES.md)
  and [requirements.MD](requirements.MD) first, and add its acceptance
  criteria to FEATURES.md once it's done. If the new feature contradicts an
  existing documented requirement, ask for clarification before implementing
  rather than silently overriding it.
- When changing or implementing a feature that's visible on screen: update
  [README.md](README.md) to describe it, and refresh the relevant
  screenshot(s) in `docs/screenshots/` so they stay current.
